Applied Migration: the Fluid Block Now Says "Fluid Physics"

Status of this file. APPLIED, 2026-11-27. Baseline dc73e8ae7; the change is commit 7549cb8b2, made by the repository's own commit process. The deploy folder was rebuilt in the same pass. Two old URLs are dead (§9).

What this file is for. What changed, how it was done, and how to recheck it. It is written so the work can be repeated on a different term, and so the new vocabulary cannot drift back unnoticed.

A note on spelling. This record never writes the retired term. It calls it the old name throughout. That is deliberate: the instruction was zero occurrences anywhere in the corpus, internal articles included, and this file is an internal article that gets published. The old name is recoverable at any time from the baseline commit:

git show dc73e8ae7:physics.md | grep '^## Biquatern' | grep -i fluid   # the old block heading

The method in five lines.

  1. Two scopes, not one. The corpus was converted wholesale; articles_external/ only where it carries our own titles and slugs, because it also carries other authors' sentences.
  2. Protected vocabulary first. Citations and quotations were masked with sentinels before any replacement ran, then restored. A plain sed would have rewritten a book's title.
  3. Order matters. Hyphenated before spaced; capitalised alongside lowercase; adjectives in a separate pass.
  4. Renames are part of the migration. Three files moved, so two published addresses changed, so the build had to run and prune.
  5. The commit is the record. Reversal is git revert 7549cb8b2; nothing here respells what was removed.

4. The Method, Step by Step

The reusable part. Written so another agent can apply the same pattern to a different term without rediscovering the traps in §6.

4.1 Step 0 — A baseline you can measure against

Never take "before" from a scan run after editing. Record the starting commit and take every before/after pair from git show <commit>:<path>. The count stays auditable, and the gitignored areas — which have no other history — get their numbers written down before anything is touched.

BASE=$(git rev-parse HEAD)     # dc73e8ae7 here
git status --porcelain         # must be empty

4.2 Step 1 — Scope as a file list, not a glob

The load-bearing decision: split the tree in two.

FULL   = physics.md maths.md index.md articles_physics articles_internal articles_maths
NARROW = articles_external     # only our own titles, slugs, and cross-references

articles_external/ holds conversions of other people's papers. A blanket pass there rewrites quoted sentences, which the instruction forbade. That folder got the narrow pass only; one editorial sentence of our own was then fixed by hand.

4.3 Step 2 — Mask the protected vocabulary before anything runs

The old name is a substring of the book title being cited and of one external paper's title, so a chain of str.replace() calls corrupts both. Swap each protected string for a sentinel, replace, swap back.

PROTECT = [BOOK_CITATION, PAPER_TITLE]           # exact strings, asterisks included
PH = {f"\x00P{i}\x00": s for i, s in enumerate(PROTECT)}

def mask(t):     return reduce(lambda x, kv: x.replace(kv[1], kv[0]), PH.items(), t)
def unmask(t):   return reduce(lambda x, kv: x.replace(kv[0], kv[1]), PH.items(), t)

A NUL-byte sentinel is safe: no legitimate Markdown contains \x00, and the token survives every later substitution because it contains none of the target letters. Do not use a bracketed placeholder such as [[PROT]] — any later pass that touches brackets eats it.

The mask is exact, asterisks and capital included. That is the point: it protects the citations as written and does not protect our own longer titles from being renamed.

4.4 Step 3 — Run the replacements, hyphenated first

def convert(t):
    t = mask(t)
    t = t.replace(HYPHEN_LOWER, HYPHEN_LOWER_NEW)     # 1. compound, lowercase
    t = t.replace(HYPHEN_TITLE, HYPHEN_TITLE_NEW)     # 2. compound, capitalised
    t = t.replace(SPACED_LOWER, SPACED_LOWER_NEW)     # 3. phrase, lowercase
    t = t.replace(SPACED_TITLE, SPACED_TITLE_NEW)     # 4. phrase, capitalised
    return unmask(t)

Two ordering rules, both learned by running it:

  • Hyphenated before spaced. The forms do not overlap textually, but this keeps the model one-directional: a later spaced rule can never create a compound it then has to revisit.
  • Capitalised alongside lowercase. Headings, H1s, and menu links are capitalised; body prose is not. Replacing only lowercase leaves every title half-renamed — a failure mode that a lowercase-only grep reports as success.

The spaced rule maps two words to two words. It must not emit the hyphenated form, which would turn prose sentences into slugs.

4.5 Step 4 — The adjective form is a separate pass

The plural does not contain the adjective, and the replacement chain that fixes the plural leaves the adjective untouched. Two occurrences survived the main pass for exactly that reason. Handle it explicitly:

<term>-mechanical  →  <term>-physical

4.6 Step 5 — Rename the files, then let git prove it

Three mv calls, and no edit to the paths elsewhere, because the slug replacement in §4.4 had already rewritten every link and backticked path pointing at them. Confirm with git diff --find-renames: it reports R097 and R094. A delete-plus-add at low similarity would mean the bodies were rebuilt rather than edited — a different and worse change.

4.7 Step 6 — Sitemaps: regenerate, do not hand-edit

build.py writes the three sitemaps from the corpus, so their change is a consequence of the rename. They were patched by hand only because the deploy had not been rebuilt yet; the build then rewrote them identically. If a build follows, edit nothing.

4.8 Step 7 — Build, and let the build prune

./.venv/bin/python build_diff.py

build_diff.py rebuilds only pages whose .md is newer, then runs both prunes. The prunes complete the rename: prune_orphans() deleted the three pages whose source had moved. Without the build the old addresses would still exist in the deploy folder while the source said otherwise — the worst state, because it hides the breakage. The build also rewrote build_state.

6. Traps, Including Three This Run Hit

  1. The plural is not the adjective. A verification regex written as <term>[\s\-]mechanical? matches neither form correctly — the ? applies to al, so it catches mechanic and mechanical and silently misses every plural. This run produced a false "before = 0" from exactly that pattern. Use alternation.
  2. Count diff deltas, not matcher hits. A matcher that includes a form the replacement does not handle inflates the count. This file carried 213 for a while; the diff says 210.
  3. The audit is part of the measurement. The earlier draft quoted the term 77 times, so a raw scan of "the tree" read 300 rather than 223. Exclude the record explicitly in both the baseline and the guard, and state the number, so a reader who re-runs the scan does not think the migration failed.
  4. Gitignored is not unpublished. articles_internal/ is gitignored but is in COLLECTIONS, so articles_internal/audits/*.md is built into the deploy folder even though no menu links it. "Internal" means "not in the menu", not "not on the web". Any term kept in an internal note is a published occurrence.
  5. An autocommit process may commit your work. This migration was committed as 7549cb8b2 by the repository's own process, not by an explicit git commit. Do not assume an uncommitted state persists between steps, and re-read git log before reporting that nothing is committed.
  6. Case variations escape exact pairs. The replacement pairs are exact strings; an unusual capitalisation not in the list survives. Check before declaring zero.
  7. Pruning has no redirect. A rename is a URL deletion. See §9.

7. Recheck Procedure

Read-only. Run from the repository root.

The guard. It builds the pattern from parts so that this record can search for a term it does not spell. It must print CLEAN.

A='fluid'; B='mechanics'; BOOK="*Fluid ${B^}*"           # the cited book's title
grep -rIn --include='*.md' -iE "$A[ -]${B}([^a-z]|$)|$A[ -]${B}al" \
  physics.md maths.md index.md articles_physics articles_internal articles_maths \
  | grep -vF "$BOOK" \
  || echo CLEAN

One exception, and it is the one the instruction named:

  • the cited book's title, $BOOK — nine Further Reading entries.

This record is not excused. It holds zero occurrences and the guard proves it. Any other line means the term has drifted back, most likely through a new article that copied an old sentence, or a pasted external conversion.

Idempotence. Re-running §4.4 on the current tree must change no file. If it changes one, the mask leaked or a capitalised variant escaped the pair list.

Where the truth lives. The authoritative record is the commit, not this prose:

git --no-pager diff --find-renames dc73e8ae7 7549cb8b2

That diff is the reversal key, the audit trail, and the proof of every number above.

9. Consequences and Follow-Ups

  1. Two URLs are dead. build.py has no redirect mechanism (verified). Host-level redirects work on GitLab and Codeberg; GitHub Pages cannot, so each old path needs a stub page that meta-refreshes to its replacement. That is the only host-independent fix.
  2. Inbound links from outside the corpus are unmeasurable from this tree. The menu and 33 internal references are updated; what the wider web holds is unknown.
  3. The deploy folder is consistent but is a build artefact — do not edit it by hand.
  4. articles_external/ keeps four quotations by design. If zero occurrences is ever demanded including quotations, the honest options are to drop the quotation or footnote it; do not silently edit another author's sentence.

10. Reversal

One command, because the migration is one commit:

git revert --no-commit 7549cb8b2
git status                        # expect three renames back, 33 files restored, sitemaps restored
./.venv/bin/python build_diff.py  # rebuild the pages, prune the new orphans

No hand-written reversal key is kept here. The commit is a more faithful record than any prose summary, and this file must not become the last place in the tree that still spells what was removed. For a scripted reversal, generate it from the diff (git diff -R dc73e8ae7 7549cb8b2) rather than transcribing it.
